# Markdown 博客写作与上传规范

本文件是博客内容的管理说明。所有正式文章放在 `app/blog/posts/`，每篇文章对应一个 `.md` 文件。

## 一、推荐工作流程

1. 先在任意目录编写 Markdown，并保持 `draft: true`。
2. 按下方规则填写 Frontmatter 和正文。
3. 将文件名改为合法 Slug，例如 `celeste-failure-and-depression.md`。
4. 把文件复制到 `app/blog/posts/`。
5. 本地检查文章列表、详情、图片、公式和搜索结果。
6. 准备公开时删除 `draft`，或改为 `draft: false`。
7. 运行构建检查；没有内容校验错误后再发布网站。

## 二、带注释的完整模板

Frontmatter 必须放在文件最顶部，并由两行 `---` 包围。以下以 `#` 开头的说明可以保留，系统会忽略它们。

```markdown
---
# 必填：页面标题。正文不需要再写一级标题。
title: "文章标题"

# 必填：发布日期，推荐统一使用 YYYY-MM-DD。
date: "2026-07-13"

# 必填：一个稳定的大分类；同类文章复用同一名称。
category: "工程札记"

# 必填：至少一个 Tag；建议使用简短的大写英文且不要重复。
tags: ["SIGNAL", "SENSOR", "NOTES"]

# 可选：删除后自动提取正文第一个自然段。
excerpt: "需要手动控制列表文案时填写摘要。"

# 可选：写作和校对期间设为 true，公开时删除或改为 false。
draft: true

# 可选：只有需要列表重点标记时才设为 true。
featured: false

# 可选：精确定时发布必须包含时区；只写 date 则按当天零点处理。
# publishAt: "2026-08-01T09:00:00+08:00"

# number 和 readingTime 不需要填写，系统会自动生成。
---

这里是正文第一个自然段。未手动填写 excerpt 时，系统会从这里生成摘要。

## 第一个章节

正文从二级标题开始。

### 子章节

继续编写内容。
```

## 三、基础信息规则

| 字段 | 是否必填 | 手动填写规则 |
| --- | --- | --- |
| `title` | 是 | 非空字符串；使用正常书名号，不在正文重复写 `# 标题`。 |
| `date` | 是 | `YYYY-MM-DD` 或 `YYYY.MM.DD`；迁移旧文时保留最初发布日期。 |
| `category` | 是 | 每篇只填一个大分类；优先复用已有分类名称。 |
| `tags` | 是 | JSON 数组，至少一项；建议大写英文，不能有空值或重复项。 |
| `excerpt` | 否 | 列表摘要；通常删除并使用自动摘要，需要精确文案时才填写。 |
| `draft` | 否 | `true` 表示全站隐藏；`false` 或删除表示可以公开。 |
| `publishAt` | 否 | 精确发布时间；完整时间必须带 `Z` 或 `+08:00` 等时区。 |
| `featured` | 否 | 只接受 `true` / `false`，普通文章保持 `false`。 |

系统自动生成：

- `number`：按实际发布时间从旧到新编排的三位档案编号。
- `readingTime`：根据中文字符数和其他语言词数计算。
- `excerpt`：未手动填写时，从正文首个自然段生成。
- `slug`：直接使用文件名，不读取 Frontmatter 字段。

旧文章中的 `number` 和 `readingTime` 会被兼容读取但忽略。不要在新文章中填写它们。

`author`、`source`、`slug` 等字段目前不属于公开结构，直接填写会触发未知字段错误。公开身份固定使用 `reflex4`；旧站来源可写成 Frontmatter 内的 `# 迁移备注：...`，不会显示在页面上。

## 四、文件名与 Slug

文件名决定文章地址：

```text
celeste-failure-and-depression.md
→ /blog/celeste-failure-and-depression
```

只允许：

- 小写英文字母 `a-z`
- 数字 `0-9`
- 单个连字符 `-`

不要使用中文、空格、下划线、连续连字符或大写字母。每个文件名必须唯一。

## 五、正文书写规则

- 页面会使用 `title` 自动渲染唯一的一级标题，正文从 `##` 开始。
- 章节使用 `##`，子章节使用 `###`，不要跳过标题层级。
- 段落之间保留一个空行；不要用大量空格控制排版。
- 图片使用 `![替代文本](图片地址)`；替代文本应描述图片内容，避免空白。
- 外部图片必须使用可公开访问的 HTTPS 地址，发布前检查是否仍能加载。
- 代码块写明语言，例如围栏起始行 ```` ```ts ````；数学公式使用 `$...$` 或 `$$...$$`。
- Tag、分类和正文标题不要承担同一职责：分类组织主题，Tag 描述关键词，标题表达文章内容。

## 六、上传前检查清单

- [ ] 文件名已经改为合法且唯一的英文 Slug。
- [ ] Frontmatter 位于第一行，开头和结尾都有 `---`。
- [ ] `title`、`date`、`category`、`tags` 全部填写。
- [ ] 没有添加 `author`、`source`、`slug` 等未支持字段。
- [ ] 正文没有重复一级标题，章节从 `##` 开始。
- [ ] 图片有替代文本，并且外部链接能够访问。
- [ ] 校对期间保持 `draft: true`。
- [ ] 公开前删除 `draft` 或改成 `false`。
- [ ] 在列表、详情和搜索中完成一次本地检查。
- [ ] 最终构建没有内容校验错误。

## 七、旧文章迁移备注

旧文章迁移时优先保留原始标题、发布日期和正文，不把旧站作者信息直接带入公开 Frontmatter。先修正文件名、标题层级和图片替代文本，再决定分类、Tag 与摘要。
