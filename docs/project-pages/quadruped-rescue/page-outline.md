## 一、页面定位

建议公开标题：**面向自主巡检的四足机器人系统**。

建议副题：**多源感知、定位导航与硬件搭建记录**。

已实现路由：`/projects/quadruped-inspection`，替代第一版的救援定位路由建议。规划文档继续保留在当前目录，避免无必要迁移。

页面以团队的巡检系统为背景，以 reflex4 的硬件搭建工作为个人视角。读者应能理解：系统要完成什么任务，硬件如何组成实验平台，软件如何利用这些输入，以及哪些已经有实验或工程依据、哪些仍需整机验证。

最新巡检系统约占正文 85%，前期救援研究控制在 10–15%。不按三份报告分别做三个项目，不用早期救援实验充当最新巡检系统的验收结果。

### 公开口径

- 公开身份：`reflex4`。个人职责：`硬件搭建`。
- 项目原名、学校、团队名单、竞赛、合作单位、精确时间线和商业数据默认省略。
- 当前状态暂概括为“已形成硬件与导航工程基础，完整巡检链路仍需联调与场景验证”。此句依据材料的详细工程章节，正式实现前核对最新进度。
- 定位、识别、导航与平台属于团队系统介绍，不能自动归为本人工作。
- 不把“参与硬件搭建”扩写成自研整机、设计所有电路、编写驱动、完成标定或主导项目。

首版建议约 1,600–2,200 字、6–8 个有效图位。先让读者看到实物，再解释搭建与系统关系，最后给出验证记录和前期研究。材料不足时删减，不用占位成果填满篇幅。

## 二、八章阅读结构

### 00 / 封面：一套面向巡检的机器狗实验平台

**读者获得：** 项目对象、应用方向、个人角色与当前阶段。

建议导语：

> 这个项目探索用四足机器人完成预设路线上的观察与记录，将多源感知、定位导航与巡检任务连接起来。我在团队中负责硬件搭建，本页记录实验平台的组成，以及它如何为后续联调与验证提供基础。

页面元素：

- 通用项目标题与一张脱敏后的整机照片。
- 一行角色信息：`reflex4 / 硬件搭建 / 团队协作项目`。
- 能力方向标签：`多源感知`、`定位导航`、`巡检探索`。
- 状态短注：“硬件与工程基础已形成，完整链路持续验证”，按最新实际进度更新。
- 两个锚点入口：“查看硬件搭建”“查看验证记录”。

**素材：** `PH-01`，优先真实整机照，去除设备资产标签与场地标识。无获准照片时使用标明“结构示意”的原创轮廓图，不用虚构工厂实景或灾难氛围图。

### 01 / 任务：从走完一条路，到留下可复核的记录

**读者获得：** 巡检需要解决的具体问题，而非泛化的市场痛点。

以“沿固定路线，到指定设备点位采集信息”的典型任务作为说明：

1. **到达位置：** 室外道路、建筑入口与室内通道的定位条件不同。
2. **采到可用信息：** 图像、点云、时间和机器人位姿需要能够关联。
3. **留下可复核记录：** 观察结果应对应点位与任务，疑似异常交由人员判断。

这是巡检目标的说明，不是已完成整机演示的描述。正文避免市场规模、政策综述和“替代所有人工巡检”的口号。

**素材：** 一条原创简化任务路线，使用虚构点位与布局，明确标注“任务示意”。不使用可识别工厂平面图，不以删除经纬度代替地图脱敏。

### 02 / 系统：移动平台、机载计算与任务管理如何配合

**读者获得：** 硬件与软件在整套系统中的分工。

主图按四层组织：

| 层次 | 展示内容 | 当前表达方式 |
| --- | --- | --- |
| 移动与采集 | 四足载体、激光、视觉、IMU、卫星定位模块 | 材料记载已有硬件基础，具体配置待核对 |
| 接入与机载计算 | 同步、供电、数据接入、时间与坐标处理、边缘计算 | 展示功能关系，不直接断言每项均完成整机验证 |
| 定位与导航 | 局部定位、全局位置参考、地图、路径规划、局部控制、状态监控 | 材料记载已有导航代码与本地测试基础 |
| 巡检任务与记录 | 点位任务、采集记录、异常提示、人工复核、设备档案 | 完整平台与任务闭环仍含规划和待联调内容 |

示意关系：

```text
传感器 → 接入与时空对齐 → 定位 / 地图 → 规划与控制 → 运动载体
                    └→ 目标与点位关联 → 巡检记录 → 人工复核
任务点位 ─────────────────→ 规划与控制
运行状态 ─────────────────→ 运动输出检查
```

主图标注“功能关系示意”，每层分别使用文字标记 `硬件基础 / 代码基础 / 设计方向 / 待核实`。不能把部分代码已经存在画成整个任务链路全部通过。

**素材：** 原创 HTML/SVG 分层图＋`PH-03` 设备布局照。型号不是必备信息，默认用类别；实际视觉输入、定位主干存在材料差异，见核对文档。

### 03 / 我的工作：把硬件搭成可继续联调的实验平台

**读者获得：** reflex4 已确认的个人贡献。这是页面的核心章节，篇幅和实物图优先于算法介绍。

开头可确定写为：

> 我在项目中负责硬件搭建。下面从平台组成与实际搭建记录出发，说明各部分承担的作用。

建议采用“整机概览 → 局部细节 → 接入记录”的顺序。以下是内容采集框架，不是已确认的个人工作清单：

| 内容位置 | 需要讲清楚的问题 | 待补充的真实记录 |
| --- | --- | --- |
| 传感器与移动载体 | 哪些设备装到了哪里，实际由我搭建的部分是什么 | 脱敏整机照、安装位置与个人搭建范围 |
| 计算、供电与连接 | 数据和供电如何组成平台，搭建中有哪些具体约束 | 可公开的结构图、机载模块照片与实际处理的问题 |
| 从组装到接入 | 完成了哪些检查，哪些工作交接给其他模块继续做 | 上电、设备接入、数据流检查等真实记录，按实际有无填写 |

每个实际案例遵循：**需要解决的问题 → 本人做出的搭建处理 → 可以看到的结果 → 尚需继续联调的部分**。例如是否遇到固定、空间、供电或连接问题，应由用户提供后写入，不代编经历。

职责边界：

- 同步板“安装或接入”和“电路设计或固件开发”不是同一贡献。
- 传感器“装上平台”“有数据输出”“完成标定”“参与融合”“通过整机测试”分别记录。
- 算法、驱动、标定、导航控制等只有经用户确认属于本人职责，才能进入第一人称描述。
- 商用四足底盘或传感器不得描述为本人自研整机。

**素材：** `PH-09A` 一组脱敏局部照片＋简化连接关系图，优先实物，必要时复用并局部放大 `PH-03`。不公开完整接线、引脚、参数矩阵、设备序列号和未公开电路细节。

本章待填内容保留在规划文档中；正式页面不显示“待确认”卡片或空白职责清单。没有更多记录时，宁可只保留真实简述与获准照片。

### 04 / 软件如何使用这些输入：定位、巡航与观察

**读者获得：** 硬件搭建在团队系统中的作用。以团队视角写，不把算法推导作为个人工作展示。

**A. 连续定位的基础。** 说明时间与坐标一致性的必要性；局部观测提供相对运动估计，卫星观测在有效条件下提供全局参考。传感器越多并不自动意味着更可靠，观测质量和版本配置仍需验证。

**B. 路线与局部控制。** 用通道出现临时障碍的示意，解释规划与局部控制的关系。材料记录了导航工程、点云处理、局部控制与监控基础；“绕行、恢复任务、异常停车”的整机行为需另有运行证据。

**C. 到点观察与人工复核。** 展示“采集 → 关联点位与位姿 → 留下记录 → 人工复核”的设计方向。完整管理平台与工单流程尚不能写为已上线能力。

只保留短技术注释；算法名称与版本确认后才进入正文。不同版本的 UKF、FAST-LIO2、FAST-LIVO2 等不能直接堆成当前系统的统一技术栈。

**素材：** 一幅导航任务示意＋一张获准运行截图即可。示意轨迹明确标注“规划示意”；没有实机证据时不制作看似已经完成巡检的模拟演示视频。

### 05 / 验证：硬件、代码和整机任务分别到了哪一步

**读者获得：** 可核对的完成程度。这是全页证据中心，不做大数字成就墙。

| 验证层级 | 可以展示的内容 | 需要的证据与边界 |
| --- | --- | --- |
| 硬件搭建与接入 | 设备组成、已完成的搭建与数据接入检查 | 实物和接入记录；设备存在不能证明同步、标定或融合有效 |
| 定位与建图实验 | 与当前版本对应的地图、轨迹或短路线实验 | 版本、场景、真值、指标定义、重复次数及原始数据；旧版另标 |
| 导航代码与监控 | 已形成的工程模块、本地代码与接口测试 | 对应测试报告与版本；不能称作全部实机测试通过 |
| 整机巡检与故障处理 | 如已有记录，展示路线、到点、障碍处理与人工接管 | 实际运行条件和完整记录；没有证据时保持待验证状态 |
| 巡检记录与复核 | 已实现部分的真实功能或明确设计图 | 不能用平台原型图证明端到端任务闭环已运行 |

每条正式实验记录包含：**版本 / 测试条件 / 指标定义 / 样本与统计方式 / 结果 / 局限 / 数据性质**。

第一版不直接搬用材料中的精确性能数字。优先挑选条件最完整的一组定位记录、一项接入记录和一项工程验证；其他内容删除或只作状态说明。

特别注意：

- 短直线误差、RPE 和累计漂移率不是同一个指标，不能混用。
- 材料中的本地代码测试记录不是本次网站任务执行的验证结果。
- 软件发出零速度指令不能证明机械制动性能。
- 巡检目标完成率、识别率和记录完整率若是拟定指标，不能写成已经取得的成绩。

**素材：** `PH-07A/B/C` 按获准证据择用；曲线只由可公开数据重绘，不补造点值，不将删除坐标的真实地图直接视为安全素材。

### 06 / 前期积累：救援研究留下了哪些技术问题

**读者获得：** 最新巡检方向的研究背景，控制为一个短章节，不再展开完整救援项目宣传。

建议正文骨架：

> 前期研究围绕地面机器人的定位与救援感知展开，涉及弱纹理下的跟踪、多源定位与人体目标的空间关联。最新巡检方案将关注点延伸到固定路线、设备点位与可复核的任务记录。

可以讲三个延续的问题：观测不稳定时如何维持定位；检测结果怎样关联空间位置；实验结果如何对应具体条件。除非用户确认，不写“全部算法已迁移”“沿用同一硬件版本”或精确研发时间线。

早期人体检测、走廊定位与建图图像，若获准展示，必须注明“前期研究记录”，不能用来证明设备异常识别、火场部署或最新整机巡检能力。

**素材：** 最多一组 `PH-04` 或 `PH-06` 早期研究图；无必要可纯文字，不复用旧封面的救援氛围图。

### 07 / 边界与下一步：从平台基础走向完整验证

**读者获得：** 当前能力边界与接下来的工程工作。

正文列 2–3 项与已有证据缺口直接关联的下一步：

- 核对当前硬件配置、时间与坐标关系，补齐接入、标定及整机联调记录。
- 在明确可通行区域验证路线、障碍处理、输入失效与任务恢复；软件响应和实际停车分开测量。
- 将真实采集结果接入点位、记录与人工复核流程，验证完整任务的数据一致性。

实际计划以团队最新安排为准。不把平面路径规划扩写为复杂地形自主通行，不把走廊实验扩写为高温、浓烟或防爆场景验证。

个人总结只写用户真实经历。可在补充后用一句具体的搭建体会收束，暂不代写“我学会了……”的故事。

结尾使用有效原生链接：返回首页项目区、阅读现有定位相关文章（接入时核对真实锚点和路径）。不提供原始 PDF、数据包、私有仓库、融资或采购入口。

## 三、视觉与素材安排

遵循 `DESIGN_SYSTEM.md` 和 `design-logs/projects.md`：采用连续项目长页，保持纸张底色、墨黑正文、墨绿工程线、铁锈橙编号与少量酒红注释。此次不改变设计系统，不新增视觉品牌或动效。

- 视觉重点为真实整机和搭建细节；结构图辅助讲解，实验图用于提供证据。
- 采用细线分栏与编号段落，避免卡片墙、科技大屏和商业路演式布局。
- 桌面结构图可跨两栏，手机改为纵向节点；比较图顺序阅读，不缩小字号塞满信息。
- 图注写明内容、画面性质及已核实的测试条件；功能示意、仿真和实测分开标注。
- 不为大纲新增动画。后续如沿用现有入场效果，必须保持减少动效模式、阅读顺序与可访问性。
- 原 `PH-*` 编号仅用于追踪素材。以本版图位安排为准；取消旧 `PH-02A–C` 与 `PH-08` 的必备要求，其余也按证据择用，旧占位清单不代表发布许可。
- PDF 原件、OCR 全文和待脱敏素材不进入仓库或 `public/`；最终只接入核对后的发布副本。
